# The versions and signing-key fingerprints of what deploy/install.sh downloads and installs on a host.
#
# Read by deploy/install.sh (pins_load) as KEY=VALUE lines, never sourced. Each key is named once, and its value
# has a fixed form. A file that is missing, a key named twice or not at all, or a value outside its form stops
# the install before anything is downloaded from these repositories: nothing falls back to the newest version.
# The file is part of the release tag, so the tag's signature covers it (docker/RELEASE_SIGNERS). install.sh
# reads the copy next to it, or, when it was downloaded alone, the copy in the clone it places on that tag.
#
# What a pin changes: a host where install.sh installs Docker or the NVIDIA container toolkit gets exactly these
# versions, from a repository whose signing key has exactly this fingerprint. An Engine or a toolkit already
# installed is kept as it is, whatever its version.
#
# A signing key's fingerprint is the primary key's, as `gpg --show-keys --with-colons <key file>` prints it on
# the first `fpr` line after `pub`: 40 uppercase hex digits.

# Docker, from https://download.docker.com/linux/<ubuntu|debian> (the key at .../gpg). A version is the upstream
# number: install.sh takes the one build of it that the repository offers for the host's codename, and refuses
# when there is none.
